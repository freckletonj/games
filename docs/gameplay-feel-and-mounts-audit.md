## Scope and confidence

This began as a source audit and has become a living implementation backlog. Checked issues mean a source change and relevant automated tests landed, **not** that human playtesting or artistic sign-off has happened. The labels **Code-confirmed**, **Player-reported**, and **Proposed** describe how an issue was originally discovered, not its current status.

Goals: family-friendly, high-skill-ceiling 2D movement, readable cause-and-effect, coherent painted characters, AI-authorable levels, and an offline self-contained HTML release.

## P0 — mechanical affordances, control responsiveness, and bugs

- [x] **01 — Bounce flowers should reward timed Jump [Code-confirmed].** In [game.js](../src/games/animal-adventure/game.js), touchSetpieces assigns an unconditional vertical velocity of -7.35 when a grounded player touches a bounceBloom. Add a short landing/takeoff skill window: passive bounce remains usable; a well-timed Jump produces a visibly higher arc. Specify a consistent impulse and test early, on-time, late, and held input. Show a clear compression / bloom / release animation and feedback.
- [x] **02 — Enforce bloom form requirements in physics [Code-confirmed].** The compiler permits bounceBloom.requires = springaroo, and route cues check it, but touchSetpieces never checks s.requires before applying the bounce. Enforce authored prerequisites in the actual interaction, not just the visuals, and add a negative physics regression.
- [x] **03 — Make vertical thermal columns genuinely lift [Code-confirmed].** Moonwing-only thermal handling subtracts 0.18 velocity per 60 Hz step and then applies 0.27 gravity: net acceleration is **+0.09 downward**, absent other impulses. It also caps upward velocity using Math.max(-3.5, ...). Define a true net upward force, terminal rise speed, smooth entry/exit, and camera/readability cues. Decide explicitly whether non-flying forms receive weaker wind assistance; never render an updraft that feels entirely inert. Keep wind-ring recharge distinct.
- [x] **04 — Give bubbling water vents a meaningful passive current [Code-confirmed].** bubbleVent applies lift only if form is Tidefox **and Jump is held** near a small trigger. Rendered bubbles otherwise read as force without force. Give vents an upward flow field upon entering the column, with stronger controllable boost for swimmers and clear physics/visual bounds. Test still, moving, and descending approaches.
- [x] **05 — Make swimming momentum-based rather than zero-buoyancy hovering [Code-confirmed].** Tidefox underwater vertical speed is set directly to (Down - Jump) × 2.45, so neutral input gives exactly zero vertical velocity. Add gentle natural sinking with drag/buoyancy, Jump to swim upward, Down to dive faster, and a reliable surface breach. Clarify accessible shallow-water movement for the explorer versus Tidefox-only deep-water safety; currently non-Tidefox is damaged/teleported after 0.8 seconds in water. Preserve the underwater relic route.
- [x] **06 — Buffer Moonwing flap taps and improve cadence [Code-confirmed].** A Jump press during the 0.15-second flap cooldown is discarded, so a correctly intended input can cost height with no wingbeat. Implement a modest input buffer and forgiving release/repress threshold, with an obvious 4-charge cue, distinct successful flap sound/animation, and no free lift from holding Jump. Verify frame-rate independence, rapid taps, and all four charges under real keyboard/gamepad input.
- [x] **07 — Make catch orbs bounce or roll with terrain [Code-confirmed].** Orb starts at a fixed forward/upward velocity and disappears on first solid/platform contact. Add a controlled low bounce and ground-following horizontal trajectory over slopes, ledges, and lower ground so creatures below the player are catchable. Preserve precise contact with the intended animal, finite lifetime, avoidance of walls, and no unintended tunneling or capture through rock.
- [x] **08 — Eliminate animal direction thrashing [Code-confirmed mechanism; player-reported visible symptom].** updateAnimals immediately reverses dir when blocked, then may reverse it again based on a new dx the next frame. Separate *facing* from *desired movement*, add turn hysteresis / minimum dwell, and prevent oscillation at slopes, cliffs, lure targets, and range boundaries. Test a blocked pursuer for zero repeated 60 Hz left-right flips.
- [x] **09 — Remove arbitrary chase leashes while preserving sensible habitats [Code-confirmed].** Movement is unconditionally clamped to homeX ± 125, with patrol limits and a floor-height-vs-homeY threshold of 33. Let hostile AI chase beyond patrol zones when terrain/navigation permits, stop naturally at real obstacles, and return to habitat after disengaging. Distinguish patrol, investigate-food, warn, attack, recover, and return states. Avoid placing invisible fences in creature combat.
- [x] **10 — Make two-treat feeding/capture reliable in normal gameplay [Player-reported; code risk verified].** Favorites award trust 60 then 60; eating blocks pursuit for 0.8 seconds. Food becomes a lure only on collision with terrain/water, the lure search is range-limited by the animal's home and current positions, and competing animals can consume it. Reproduce rapid consecutive throws, displaced animals, slopes, water edges, and nearby competitors. Provide visible 1/2 progress, preserve trust across reasonable waiting, reserve or fairly choose lures, and guarantee an adequate catch window after the second snack.
- [x] **11 — Replace mismatched eating character art [Player-reported; integration verified].** [art.js](../src/platform/art.js) overrides each character's native atlas for eat using an independent 3×3 [states.webp](../src/assets/illustrations/states.webp) atlas; the manifests themselves already have eat animations. Review each pose side-by-side with the corresponding idle/run sprite for species, costume, palette, proportions, outline, and foot pivot. Replace/redraw mismatches or use identity-consistent native poses. The existing art test checks only visibility/difference, **not whether the character still looks the same**.
- [x] **12 — Make Cloudwhisp attacks matter in aerial play [Code-confirmed parameters; player-reported impact].** Warning begins only within 100 horizontal / 44 vertical units, winds up for 0.65 seconds, affects a forward range of 87, and applies one vx=3.8 / vy≤-1.4 impulse before normal traction resumes. Adjust anticipation/detection cone, attack timing, sustained knockback impulse or brief momentum protection, and meaningful avoidance options; telegraph the actual hazard width and preserve counterplay. Test airborne intercepts and recoverability.
- [ ] **13 — Draw thrown food as individual fruit [Code-confirmed].** Food projectiles use berryBush / nectarFruit / stardropFruit scenery sprites; a thrown berry therefore looks like a bush, not one berry. Provide separate single-fruit sprites or properly cropped atlas frames, sized for readable flight. Keep the basket only for pickups / inventory replenishment.

## P1 — new rideable creatures and systemic consistency

- [ ] **14 — Add a feedable, non-capturable Unicorn mount [Proposed].** New species/painted animation set, recognizable approach and tame cue; powerful ground acceleration, top speed, traction, and long/high jump. Favorite-food friendship unlocks mounting by **landing on its back / jumping onto it**, not by firing an orb. Mounts are not transformations and cannot be captured.
- [ ] **15 — Add a feedable, non-capturable Pegasus mount [Proposed].** Distinct coherent sprite/flight animation, same food → trust → jump-to-mount sequence, strong ground mobility and **unlimited sustained flight while mounted** (not constrained to Moonwing's four wingbeats). Specify ascend/descend controls and flight energy rules: none for unlimited flight. Make landing/dismount safe.
- [ ] **16 — Integrate mounts into collision, combat, camera, co-op, and progression [Proposed].** Rider/mount share an authoritative position, hitbox, movement state and animation; prevent an ordinary head-stomp from knocking out a friendly mount. Add mount/dismount, re-mount, death/respawn, food targeting, control prompts, speed-camera framing, P2 follow-bubble handling, and restrictions needed to prevent sequence-breaking. Separate rideable from capturable in catalog and orb capture logic.
- [ ] **17 — Replace one-frame AI reactions with readable behavior states [Proposed from current monolithic AI].** Creature-specific patrol/chase/flee/prepare/attack/recover/return transitions should retain direction and intent between frames; avoid direction changes during a warning/dash/gust unless intentionally signaled. Flying animals should navigate useful vertical space and aquatic animals should remain inside actual connected water instead of staying near a fixed home elevation.
- [ ] **18 — Ensure spells, food and orbs respect geometry at speed [Code-confirmed collision design].** Projectiles move, then sample a point hit against tiles/animals, so narrow surfaces / high relative velocities can be skipped. Add swept or sub-stepped collision as justified; resolve terrain before hitting animals behind it, and ensure bounce/honey/bubble interactions align with visible sprite and slope geometry.
- [ ] **19 — Fix food handling at water edges and during overlapping throws [Code-confirmed risk].** Food hitting water immediately becomes a lure at the hit location, but its vertical/float behavior and availability to aquatic/flying animals are not modeled explicitly. Define sinking/floating behavior by fruit and biome, prevent unreachable bait from wasting the player’s limited resources, and clarify who is eating which treat.
- [ ] **20 — Align hazard warnings, hitboxes and response time [Code-confirmed design gap].** Dash and gust warning lines should reflect actual attack extent and collision timing; increase readability near the edge of the camera, especially in Cloud Gardens. Confirm safe routes by jump-over, run-past, feeding, and form-specific counterplay without surprise contact.
- [ ] **21 — Keep mount and flower boosts from trivializing authored gates [Proposed].** Update chapter placement/progression so exceptional speed, bloom skill launches and unlimited Pegasus flight offer exciting shortcuts/rewards without breaking required creature puzzles or making existing levels empty. Introduce routes built specifically for riding and high-speed traversal.

## P2 — quality, tooling, and playtesting

- [ ] **22 — Extend semantic authoring schema for rideables and forces [Code-confirmed missing support].** [world-compiler.js](../src/platform/world-compiler.js) enumerates only eight species and three setpiece types; [levels.js](../src/platform/levels.js) has no Unicorn/Pegasus markers. Add validated mount spawns, optional roaming bounds/connected navigation surfaces, air-current strengths and water-current semantics, plus visual authoring symbols. Keep the JSON → compiler → game → art-mask feedback loop consistent.
- [ ] **23 — Expand realistic, deterministic gameplay regression coverage [Code-confirmed gaps].** Add no-cheat browser-physics tests for bloom passive/perfect timing/required form, thermal acceleration, bubble vent neutral entrance, sink/ascend/surface transitions, four buffered wingbeats, orb bounce down a slope, chase beyond old ±125 boundary, stationary boundary facing, reliable two-treat feeding, Cloudwhisp push, and both mounts.
- [ ] **24 — Add full-level end-to-end agent/playtest routes [Code-confirmed scope gap].** Existing route probes may grant forms, skip enemies, and start at a local foothold. Add a separate full-start-to-gate scenario that obtains food, befriends animals, uses transformations and mounts, crosses threats, gets the relic and returns. Keep current local geometry probes; don't label them a complete playthrough.
- [ ] **25 — Verify character/sprite continuity visually [Code-confirmed test gap].** Existing art tests decode named images and compare idle versus eating pixel differences but cannot detect another species in the eating frame. Produce a contact sheet with paired idle/eat/action/knockout frames at in-game scale; require a human identity/pivot review and optionally image similarity checks.
- [ ] **26 — Test real gamepad/co-op interaction for every new control [Proposed].** Include input tap buffering and repeat cadence, the second player's controls, mount/dismount while P2 rides the follow bubble, collision when camera moves independently, and offline build behavior on target browsers/controllers.
- [ ] **27 — Improve cinematic vertical camera and telegraph readability [Proposed].** In tall/fast aerial scenes, reveal threats and landing targets early enough that gusts and flaps can be planned. Avoid excessive text, HUD popups over play space, hidden launch pads, and art that falsely implies physical forces.
- [ ] **28 — Calibrate encounter difficulty and food economy for family play [Proposed].** A novice should see why a mistake happened and recover quickly; timed flower boosts, four flaps, feeding and mounted speed should offer skill mastery rather than frame-perfect requirements. Measure retries, bait expenditure, flight stalls and blindside hits on real players.
- [ ] **29 — Keep artwork, terrain and collision coherent [Player-reported follow-up].** Audit stretched/mismatched creature states, dynamic visual contacts, water bubble anchoring and the 16-unit collider-to-paint correspondence. Bespoke diffusion-painted per-location panels and human art review remain separate polish work, not part of this audit PR.
- [ ] **30 — Track performance and determinism with the expanded ecology [Proposed].** Current update loops all animals and filters/sorts lures each tick; adding mounts and roaming AI increases work. Measure frame time and memory in the offline build with many creatures, particles, and multiple riders before optimizing. Run fixed-input replay scenarios to catch AI flip jitter and collision regressions.

## Recommended implementation sequence

1. **Immediate feel/correctness pass (01–13)** with deterministic tests, keeping existing level data and offline release intact.
2. **Creature AI + mounts (14–21)** with new art, tame/ride behavior, and controlled progression placement.
3. **Semantic authoring, regression coverage, and playtests (22–30)**, with a fresh assessment of aerial and aquatic levels once dynamics change.

Do not infer that every reported symptom is reproduced solely because the code has a plausible cause. The implementation PR(s) should include actual browser captures, before/after measured trajectories, and relevant regression results.

## Validation contract for follow-up PRs

- **Physics**: compare vertical trajectories (frame vs y/vy), explicit bloom perfect-timing differential, current positive acceleration, natural descent and swimming effort, wingbeat input accepted inside buffer, and orb ground-contact behavior.
- **AI**: count facing changes per second at boundaries, pursue beyond old leash when an unobstructed path exists, and verify Cloudwhisp gust displacement / warning-to-impact time.
- **Capture**: normal two-favorite-treat sequence with real thrown fruit and a real moving creature; show consistent capture availability, also after near-simultaneous throws.
- **Mounts**: feeding is required; Jump onto back mounts; capture orb cannot capture; Unicorn run/jump is significantly stronger than explorer; Pegasus can sustain upward flight beyond four beats; dismount and co-op do not lose control.
- **Art**: in-game contact sheets and human checks show each eating pose is the same creature; projectile fruit is a single fruit; transitions preserve feet/scale.
- **Release**: build through scripts/build.mjs and run tests against the **unaltered** dist/wonderwood.html (including offline_launch.py), plus local deterministic tests and controller checks; do not confuse test fixtures with the shippable game.
